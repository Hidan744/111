# Нефтегазовый ИИ-ассистент — MVP на Yandex AI Studio

## Что это

Прототип "Уровня 2" из нашего плана: ИИ-ассистент с базой знаний
(методология + расчёты + нормативка + подбор оборудования + обучение),
работающий через YandexGPT. База знаний и логика обращения к модели общие
(см. `core.py`), а поверх них — четыре интерфейса на выбор:

- **`bot.py`** — консольный диалог, для быстрой проверки, что ассистент
  вообще ведёт себя правильно;
- **`bot_max.py`** — бот в мессенджере MAX;
- **`bot_telegram.py`** — бот в Telegram;
- **`app_web.py`** — отдельное веб-приложение с чатом в браузере.

├── bot.py                       ← консольная версия
├── bot_max.py                   ← бот для мессенджера MAX

## Шаг 1. Установи Python (если ещё нет)

Скачай с https://www.python.org/downloads/ — версия 3.10 или новее.
При установке на Windows обязательно поставь галочку "Add Python to PATH".

## Шаг 2. Получи API-ключ и Folder ID в Yandex AI Studio

Ты уже вошёл в AI Studio — там нужно:

1. В правом верхнем углу нажать **"Создать API-ключ"** (Create API key)
2. Сохранить выданный ключ — он показывается только один раз
3. Найти **Folder ID** (ID каталога) — обычно виден в интерфейсе AI Studio
   рядом с названием проекта/каталога, либо в разделе настроек каталога

## Шаг 3. Распакуй проект и открой терминал в этой папке

- Windows: открой папку, в адресной строке проводника напиши `cmd` и нажми Enter
- Mac: открой Terminal, введи `cd ` (с пробелом) и перетащи папку в окно терминала, нажми Enter

## Шаг 4. Установи зависимости

```
pip install -r requirements.txt
```

Если `pip` не находится — попробуй `pip3` или `python -m pip install -r requirements.txt`.

## Шаг 5. Настрой ключи доступа

1. Скопируй файл `.env.example` и назови копию `.env`
2. Открой `.env` в любом текстовом редакторе (Блокнот подойдёт)
3. Вставь свой реальный API-ключ и Folder ID вместо плейсхолдеров
   (`MAX_BOT_TOKEN` и `TELEGRAM_BOT_TOKEN` нужны только для соответствующих
   ботов — см. ниже)

## Шаг 6. Запусти нужный интерфейс

### Вариант А — консоль (быстрый тест)

```
python bot.py
```

Если всё настроено верно — увидишь приглашение "Нефтегазовый ассистент готов".
Пиши вопрос, например:

```
Скважина №14, добывающая. Дебит жидкости 45 м3/сут, обводнённость 62%.
Посчитай дебит нефти.
```

Для выхода напиши `exit`.

### Вариант Б — бот в мессенджере MAX

1. В MAX найди **@MasterBot**, отправь ему `/create`, задай имя бота
   (заканчивается на `_bot`) — в ответ придёт токен доступа
2. Впиши токен в `.env` как `MAX_BOT_TOKEN`
3. Запусти:
   ```
   python bot_max.py
   ```
4. Найди своего бота в MAX по имени и напиши `/start`

Бот работает через long polling (опрос сервера MAX) — этого достаточно для
теста и небольшой нагрузки; для прода библиотека `maxapi` рекомендует
вебхуки с HTTPS. История диалога хранится в памяти процесса отдельно по
каждому чату и сбрасывается при перезапуске бота.

### Вариант В — бот в Telegram

1. В Telegram найди **@BotFather**, отправь ему `/newbot`, следуй его
   подсказкам (имя бота и ник, ник должен заканчиваться на `bot`) — в
   ответ придёт токен доступа
2. Впиши токен в `.env` как `TELEGRAM_BOT_TOKEN`
3. Запусти:
   ```
   python bot_telegram.py
   ```
4. Найди своего бота в Telegram по нику и напиши `/start`

Тоже работает через long polling, история диалога — в памяти процесса
по каждому чату отдельно.

### Вариант Г — веб-приложение (браузер)

```
streamlit run app_web.py
```

Откроется страница чата на `http://localhost:8501` — подойдёт как
демо-стенд или временная альтернатива боту. При деплое на хостинг
(например, Streamlit Community Cloud) можно сразу дать клиентам ссылку.

## Шаг 7. Прогони тестовые кейсы по базе знаний

В `tests/cases.py` — 7 готовых кейсов на все категории задач из
`kb/00_metodologiya_yadro.md` (расчёт, расчёт с неполными вводными —
проверка, что модель не выдумывает цифры, диагностика, эффект ГТМ,
нормативная проверка, подбор оборудования, обучение стажёра). У каждого —
эталонный расчёт или чек-лист, посчитанный вручную по формулам из `kb/`.

```
python tests/run_cases.py
```

Скрипт прогонит все кейсы через реального ассистента и сохранит отчёт в
`tests/results/<дата-время>.md` — вопрос, эталон и реальный ответ модели
рядом, для сверки глазами. Добавляй сюда свои кейсы из практики по мере
использования.

## Что дальше (после того, как MVP отработал на тестовых вопросах)

1. **Прогнать 5-10 реальных кейсов** из твоей практики (можно прямо
   добавить их в `tests/cases.py`) — сверить, не ошибается ли модель, не
   путает ли формулы. Если база знаний неточна — править файлы в `kb/`,
   а не код ботов.
2. **Клонировать под новую нишу** — скопировать папку проекта, оставить
   `00_metodologiya_yadro.md` как есть, а остальные файлы в `kb/` заменить
   на новый отраслевой модуль (используй мета-промпт в конце файла
   `00_metodologiya_yadro.md`, чтобы сгенерировать черновик).

## Важно перед продажей клиентам

Формулы в `02_raschety_debit_gtm.md` — это стандартные общепромысловые
методики для старта, не проприетарная методика конкретного предприятия.
Обязательно сверь их со своей практикой (в том числе с наработками из
проекта нефтяного бота) и поправь файл под реальные принятые у тебя
коэффициенты и формулы, прежде чем показывать продукт клиентам.
