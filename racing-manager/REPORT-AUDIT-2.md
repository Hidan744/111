# Отчёт итерации: аудит и разделы 4–9 ТЗ

Предыдущие этапы описаны в `AUDIT.md` (логика гонки) и `REPORT-ECONOMY.md` (экономика и сохранения).

## 1. Карта проекта

- `game.html` (~370 КБ, ~3300 строк): игра целиком, одна IIFE. `index.html` собирается из него.
- Внешние зависимости:
  - three.js r128 (cdnjs) — без него гонка показывается схемой трассы;
  - Google Fonts — без них используются системные шрифты.
- Сервис-воркера нет. Поэтому игра **не работает офлайн как PWA**: проверено, что без сети она запускается из файла, но без 3D и без фирменных шрифтов. `manifest.webmanifest` даёт только иконку и название при добавлении на главный экран.
- Системы и функции:

| Система | Функции |
|---|---|
| Состояние | `S` — карьера, `W` — уик-энд, `R` — гонка |
| Конфигурация баланса | `BAL` (новое), `TEAM_DEFS`, `COMPS`, `FACS`, `UPG`, `SPEC`, `GOALS` |
| Экономика | `money`, `finClose`, `finishRace` (раздел «экономика»), `endSeason`, `mandPerRace`, `incPerRace`, `fomPrize` |
| Симуляция гонки | `lapModel`, `simLap`, `tyreWear`, `compWear`, `raceOptions`; ИИ — `aiDecide`, `aiMode` |
| Развитие соперников | `finishRace` → `aiDevBudget` |
| Карьера | `endSeason`, `retireCheck`, `marketCard`, академия, лиги, регламент |
| Сохранения | `save`, `load`, `readSave`, `exportSave`, `importSave` |
| Интерфейс | `render` и `v*` (экраны), один делегированный обработчик кликов |
| Визуализация | `init3D`, `draw3D` (three.js), `drawTrack` (2D) |

## 3. Долгосрочный баланс: серии карьер

Инструмент: `tests/career-batch.js` — быстрые карьеры без отрисовки на тех же функциях игры, примерно 1 секунда на сезон.

- Сводка по сериям: `tests/mc-summary.py`.
- Стратегии бота:
  - **spend** — сбалансированное развитие;
  - **save** — без развития;
  - **aero** — всё в одну характеристику;
  - **infra** — сначала база;
  - **risky** — без резерва денег.
- Прогонов: 100 для spend, по 40 для остальных стратегий; горизонт 1, 3 и 5 сезонов.
- Всего около 1000 карьер.

### До и после исправлений (стратегия spend, 100 карьер)

| Команда | Сезон | До: место (лучшее..худшее), уволен | После |
|---|---|---|---|
| Топ (Ред Булл) | 3 | 7,6 (4..11), уволен в 100% | **2,4 (1..5)**, уволен в 29% |
| Топ | 5 | — | **2,0 (1..4)**, 57%: цель «1-е место» строгая |
| Средняя | 3 | 10,8 (8..11), 98% | 9,6 (5..11), 28% |
| Слабая | 5 | 11,0 (11..11), 70% | **9,3 (5..11)**, 42% |
| Своя команда | 5 | 11,9 (10..12) | 11,5 (9..12), 0% |
| Отставание болида от лучшего, слабая команда, 5-й сезон | — | −15,9 | **−4,2** |

### Стратегии: есть ли доминирующая (после исправлений, 5 сезонов)

| Команда | spend | save | aero | infra | risky |
|---|---|---|---|---|---|
| Топ | 2,0 место | уволен к 3-му (8,1 место) | уволен к 5-му | 2,8 | **1,9**, но резерв ~5 млн |
| Средняя | 10,1 | 10,5 | 10,0 | **8,9** | 9,3 |
| Слабая | 9,3 | 10,2 | 10,0 | **7,9** | 9,1 |
| Своя | 11,5 | 11,9 | 11,6 | 11,8 | 11,8 |

Выводы:

- Ни одна стратегия не выигрывает везде.
- Копить невыгодно: команда без развития скатывается, а деньги сверх годового резерва забирают владельцы.
- Вкладывать в одну характеристику — проигрыш.
- База — долгосрочная стратегия: в первом сезоне она хуже (средняя 7,3 против 6,5 у spend), к пятому лучше.
- Игра без резерва даёт результат, но держит команду на грани.

Прочее:

- **Банкротств — 0** во всех сериях. Доля сезонов с отрицательным балансом — 0–3%.
- **Стратегии пит-стопов**:

| Пит-стопов | Доля гонок |
|---|---|
| 0 | 0–1% |
| 1 | 60–70% |
| 2 | 25–32% |
| 3 и больше | 5–8% |

- **Победы** у топ-команды: 10,6% стартов пилота (около 5 побед команды за сезон). У слабой — 0,1%.
- **Сходы** по всем машинам: 0,2–0,5% стартов. Это низко по сравнению с реальной Ф-1, но по вашему требованию износ узлов зависит от манеры вождения, а не от случайности.

## 4. Интерфейс (раздел 6)

- **Главный экран**: новый блок сверху.
  - Сводка: место и цель, бюджет и на сколько этапов его хватит, обязательные расходы до конца сезона.
  - «Требует внимания»: до 5 пунктов по важности с кнопкой действия. Красным — то, что сломает гонку (узел не доживёт до финиша, нет пилота, долг). Жёлтым — важное (спонсоры, голосование, уходящий пилот, нехватка денег). Синим — возможности.
  - Рекомендация «что выгоднее всего» считается по реальным данным: прирост от доработки × вес характеристики на ближайших 5 трассах ÷ цена.
  - Проверено на 1300 px и 390 px.
- У каждого узла теперь видно, на сколько гонок хватит ресурса. Узлы, которые не доживут до финиша, выделены красным.
- Опасные действия требуют подтверждения: замена узла сверх лимита, разрыв со спонсором (показана неустойка), замена карьеры новой, увольнение, сброс.

4. Плавные переходы камеры между режимами.

**Требуют переработки сцены**:

2. Здания паддока по реальным схемам.
3. Повторы ключевых моментов: запись позиций и воспроизведение.

**Требуют другого движка**:

1. Кинематографические камеры с постобработкой уровня Motorsport Manager.
2. Физически корректный дождь и волны брызг.

## 6. Архитектура (раздел 8)

- Сделано без разбиения файла:
  - балансные параметры экономики в одном объекте `BAL`;
  - все денежные операции через `money()`;
  - одна формула расходов и дохода для всех экранов;
  - логика карьеры прогоняется без отрисовки (`batchCareer`) — значит, её можно тестировать отдельно от графики.
- Остаётся (безопасный план, по одному шагу с тестами):
  1. Вынести `BAL` и данные (`TEAM_DEFS`, `CIRCUITS`, `COMPS`) в отдельный файл данных.
  2. Вынести симуляцию (`lapModel`, `simLap`, `aiDecide`) и экономику в модули без доступа к DOM.
  3. Убрать из `finishRace` смешение трёх задач: экономика, очки и показ экрана.
  4. Перейти на сборку (Vite), где `index.html` собирается автоматически.

## 9. Что осталось

- Топ-команду увольняют часто (57% к 5-му сезону): цель «1-е место» и 2 предупреждения подряд. Это решение по дизайну, а не дефект, — нужен ваш выбор.
- Своя команда растёт медленно: за 5 сезонов в среднем с 12-го до 11,5-го места, лучшее — 8-е. Бот играет просто, живой игрок будет быстрее, но, возможно, стоит усилить помощь новичкам.
- Средняя команда при стратегии spend всё ещё сползает: в среднем с 6,5-го на 10-е место к 5-му сезону. Причина пока не установлена — нужен разбор.
- Визуальные улучшения из плана не реализованы: по ТЗ сначала нужно ваше согласование.
