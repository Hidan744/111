# Решение по движку для Пит-Уолл

## Ограничивает ли нынешний стек игру

По фактам этого проекта — пока нет.

- Вся игровая логика (симуляция, экономика, карьера) работает и тестируется: около 1000 карьер прогоняются без графики.
- Интерфейс менеджера сделан на HTML/CSS. Это самый удобный инструмент для таблиц, финансов и меню.
- 3D-сцена на three.js даёт 30–180 тысяч треугольников и 53–144 вызова отрисовки — далеко от предела браузера.

Нынешние ограничения картинки (процедурные плоские трассы, простые модели) — это недоделанный контент, а не предел движка. Переход на другой движок сейчас преждевременен. Он оправдан, только если цель — кинематографическая 3D-трансляция уровня Motorsport Manager на слабых телефонах.

## Сравнение

Оценка от 1 до 5, где 5 — лучше.

| Критерий | A. Браузер (TypeScript + three.js/Babylon.js + Capacitor) | B. Godot 4 | C. Unity 6 (URP) |
|---|---|---|---|
| Качество 3D-графики | 3: хорошо при аккуратной оптимизации | 3–4: хороший рендер, слабее на мобильных | **5**: лучший мобильный 3D, запечённый свет, LOD, постобработка |
| Интерфейс менеджера (таблицы, финансы, формы) | **5**: HTML/CSS, уже готов | 3: Control-узлы удобны, но таблицы и вёрстку придётся строить заново | 3: UI Toolkit похож на CSS, но инструментов для таблиц меньше |
| Анимация гонок, камеры | 3: вручную в коде | 4: AnimationPlayer, сцены, Path3D для траекторий | **5**: Timeline, Cinemachine, готовые инструменты |
| Производительность на слабых телефонах | 2–3: зависит от WebView | 4 | **5** |
| Простота публикации | **5**: ссылка или сайт; Capacitor для магазинов | 4: экспорт на Windows, Linux, macOS, Android, iOS | 4: все платформы, но тяжелее сборки |
| Сложность миграции | **5**: миграции нет | 2: переписать всё на GDScript или C# | 2: переписать всё на C# |
| Повторное использование кода | **5**: 100% | 1: только формулы и данные | 1: только формулы и данные; C# близок по стилю |
| Скорость разработки одним человеком | **4** | 4: лёгкий редактор, быстрый цикл | 3: тяжёлый редактор, больше настроек |
| Стоимость | бесплатно | бесплатно (MIT) | бесплатно до порога дохода, дальше лицензия |
| Риски | производительность 3D в WebView | меньше готовых ассетов, мобильный рендер моложе | лицензионная политика, тяжёлые проекты |

**Unreal Engine** не рекомендую. Его сила — фотореалистичный рендер для ПК и консолей. Для менеджера, где игрок большую часть времени смотрит на таблицы, это непропорционально сложно: C++ или Blueprint, тяжёлые сборки под мобильные и лицензионные отчисления. Интерфейс менеджера на UMG делать заметно дольше.

## Рекомендация

1. **Сейчас — остаться в браузере.** Довести игровой процесс и баланс, затем навести порядок в коде по плану из `REPORT-AUDIT-2.md`: модули, TypeScript, Vite. Для магазинов собрать через Capacitor.
2. **Если нужна 3D-картинка уровня Motorsport Manager** — **Unity 6**, через прототип (ниже), а не через полный перенос.
3. **Godot** — если важны свободная лицензия и лёгкий редактор и не нужен топовый мобильный 3D.

## План, если переход будет оправдан (без немедленного переноса)

1. Выделить независимую модель состояния: `S`, `W`, `R` → описать схему (JSON уже версионирован, `SAVE_VER = 3`).
2. Зафиксировать правила тестами. Это уже есть:
   - `race-logic` — 9 проверок;
   - `save` — 7;
   - `security` — 5;
   - серии карьер с эталонными цифрами.

   Тесты станут спецификацией для переписывания.
3. Описать интерфейс между логикой и картинкой: на входе — позиции машин по кругу (`carProgress`), состояние пит-лейна (`pitState`), погода; на выходе — команды игрока (пит-стоп, режим).
4. Прототип в Unity: одна трасса, один болид, одна тестовая гонка, получающая позиции из JSON-записи гонки браузерной версии.
5. Сравнить картинку и FPS на реальных телефонах с нынешней 3D-версией.
6. Оценить перенос интерфейса менеджера: это самая дорогая часть.
7. Только после этого решать о полной миграции.

### Что переносится, а что нет

| Часть | Перенос |
|---|---|
| Сохраняется концептуально | формулы `lapModel`, `tyreWear`, `compWear`, экономика `BAL`, правила регламента, ИИ-решения, данные о трассах, командах и пилотах |
| Переписывается | весь код (JavaScript → C# или GDScript), интерфейс, 3D-сцена |
| Переносятся данные | составы, календари, трассы, параметры шин и узлов; формат сохранения можно оставить JSON с той же схемой |
