# Аудит Пит-Уолл: этапы 1–2

## Архитектура

- Один файл `game.html` (~274 КБ, ~2500 строк), `index.html` — та же игра с обёрткой документа.
- Внешние зависимости: Three.js r128 (CDN), Google Fonts. Без сборки.
- Весь код в одной IIFE. Глобальное состояние: `S` — карьера (localStorage, миграция в `ensureEcon`),
  `W` — уик-энд, `R` — гонка (не сохраняются).
- Интерфейс: полная перерисовка через `innerHTML` с экранированием `esc()`, один делегированный обработчик кликов по `data-a`.
- Гонка: дискретная симуляция по кругам (`simLap`) внутри цикла `requestAnimationFrame`; случайность — `Math.random` без зерна.

## Проверено, ошибок нет

Сила машины и пилота определяет результат (Спирмен 0,67–0,76 при оправданной случайности),
потеря на пит-стопе учитывается, изношенные шины стоят до ~5 с на круге, дождь меняет стратегию
(соперники переходят на дождевые за 0,3–0,6 круга), события радио совпадают с классификацией,
повторного цикла гонки нет, пользовательское имя не даёт выполнить код.

## Риски архитектуры

Монолитный файл; симуляция связана с циклом отрисовки; нет зерна случайности (нельзя воспроизвести гонку);
внутренние функции закрыты (для тестов добавлен `window.__dbg` только при `?debug`); зависимость от CDN;
перезагрузка посреди уик-энда заново разыгрывает погоду и квалификацию.
