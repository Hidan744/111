# KuCoin Spot Bot

Торговый бот для спотового рынка KuCoin на Python. Из зависимостей только `requests`.

> **Важно.** Ни одна стратегия не гарантирует прибыль. Большинство розничных
> торговых ботов на длинной дистанции проигрывают стратегии «купить и держать»,
> в основном из-за комиссий. Этот бот — инструмент, который нужно проверить
> на истории, затем на бумаге и только потом запускать на небольшой сумме,
> потерю которой вы готовы принять.

## Что умеет

- **Три стратегии** (только long, спот), выбираются параметром `STRATEGY` в `.env`:

  | `STRATEGY` | Идея | Вход | Выход |
  |---|---|---|---|
  | `trend` | следование тренду | EMA 12 пересекает EMA 26 снизу вверх, RSI < 70 | обратное пересечение |
  | `meanrev` | возврат к среднему | закрытие ниже нижней полосы Боллинджера (20, 2σ) и RSI < 30 | возврат к средней линии |
  | `breakout` | пробой канала Дончиана | закрытие выше максимума за 20 свечей | закрытие ниже минимума за 10 свечей |

  Во всех стратегиях покупка разрешена только при цене выше EMA 200 (фильтр
  тренда, `TREND_EMA=0` его выключает). Во всех стратегиях работают стоп-лосс и
  тейк-профит по ATR и опциональный трейлинг-стоп.
- **Сравнение стратегий** (`compare`): все стратегии прогоняются на одной
  истории за весь период и отдельно на каждом отрезке.
- **Риск-менеджмент**: размер позиции подбирается так, чтобы при срабатывании
  стопа терять не больше `RISK_PER_TRADE` капитала (по умолчанию 1%). Есть
  дневной лимит убытка и аварийная остановка при просадке от пика.
- **Три режима работы**, и во всех трёх работает один и тот же код стратегии:
  - `backtest` — проверка на истории с учётом комиссий и проскальзывания;
  - `paper` — бумажная торговля на живых котировках, без реальных денег;
  - `live` — реальные рыночные ордера, в пределах лимита `MAX_CAPITAL`.
- **Переживает перезапуск**: позиция, стоп и баланс хранятся в `state_*.json`.
- **Защита от случайного запуска**: для `live` нужны сразу `LIVE_TRADING=yes`
  в `.env` и флаг `--confirm`.

## Режим auto: бот сам выбирает монеты

```powershell
.\run.bat auto-backtest --days 730   # проверить режим на истории
.\run.bat auto                       # торговать виртуальными деньгами (статистика)
.\run.bat stats                      # статистика: сделки, PnL, лучшие/худшие пары, открытые позиции
.\run.bat auto --live --confirm      # реальные деньги (LIVE_TRADING=yes, ключи в .env)
```

Как это работает:

1. **Отбор пар.** Бот сам просматривает все пары к USDT на KuCoin и оставляет
   ликвидные: оборот за сутки не меньше `MIN_VOLUME_USDT`, спред не больше
   `MAX_SPREAD`, торговля разрешена. Стейблкоины, плечевые токены (`BTC3L` и т.п.)
   и пары из `EXCLUDE` отбрасываются. Из оставшихся берутся `MAX_PAIRS` самых
   ликвидных. Монеты, по которым меньше ~35 дней истории (свежие листинги),
   не торгуются.
2. **Сигналы.** На каждой новой свече (`TIMEFRAME`, по умолчанию 4 часа) бот
   считает стратегию по каждой отобранной паре. Если сигналов больше, чем
   свободных мест, берутся самые сильные: цена дальше всего выше трендовой EMA
   (в ATR).
3. **Позиции.** Одновременно открыто не больше `MAX_POSITIONS`, и одна позиция
   занимает не больше `1/MAX_POSITIONS` капитала. Каждые `POLL_SECONDS` бот
   проверяет стопы всех позиций по ценам всей биржи одним запросом.
   Дневной лимит убытка и аварийная остановка работают на весь портфель.
4. **Статистика.** Каждая закрытая сделка записывается в `trades_auto_paper.csv`
   (у реальной торговли — `trades_auto_live.csv`), и файл открывается в Excel.
   `stats` показывает итог, profit factor, лучшие и худшие пары и открытые
   позиции с текущей ценой.

В виртуальном режиме покупка идёт по цене продавца, а продажа — по цене
покупателя, плюс комиссия. Поэтому реальный спред каждой монеты учитывается.

**Ограничения.** Альткоины двигаются вместе с BTC: при падении рынка сработают
стопы почти у всех позиций сразу. Для этого и ограничено `MAX_POSITIONS`.
В `auto-backtest` попадают только монеты, которые живы и ликвидны сейчас,
поэтому он завышает результат. Решение о реальных деньгах принимайте по
статистике виртуальной торговли, а не по бэктесту.

## Установка в Windows

1. Установите Python 3.10 или новее с https://www.python.org/downloads/ и на
   первом экране установщика отметьте **«Add python.exe to PATH»**.
2. Скачайте код (кнопка Code → Download ZIP на GitHub), распакуйте архив
   и откройте папку `kucoin-bot`.
3. В адресной строке Проводника наберите `powershell` и нажмите Enter: откроется
   PowerShell сразу в этой папке.
4. Запускайте команды через `run.bat`: при первом запуске он сам поставит
   зависимости и создаст `.env`:

```powershell
.\run.bat compare --days 730
.\run.bat --timeframe 4hour compare --days 730
.\run.bat --symbol ETH-USDT compare --days 730
.\run.bat --strategy breakout backtest --days 365 --trades
.\run.bat paper
```

Синтаксис `ПЕРЕМЕННАЯ=значение команда` в PowerShell не работает. Вместо него
используйте флаги `--symbol`, `--timeframe`, `--strategy` или правьте `.env`
Блокнотом.

## Установка в Linux / macOS

```bash
cd kucoin-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # затем отредактируйте .env
```

## Порядок запуска

```bash
# 1. Сравнить все стратегии на истории за 2 года (API-ключи не нужны)
python main.py compare --days 730

# 1б. Подробно посмотреть выбранную (STRATEGY в .env) со списком сделок
python main.py backtest --days 365 --trades

# 2. Бумажная торговля минимум 2–4 недели (API-ключи не нужны)
python main.py paper

# 3. Реальная торговля: ключи в .env, LIVE_TRADING=yes, маленький MAX_CAPITAL
python main.py live --confirm
```

Историю можно сохранить один раз (`python main.py download --days 730`) и
перебирать параметры офлайн: `python main.py backtest --csv data/BTC-USDT_1hour_730d.csv`.

### Сводная таблица по парам и таймфреймам

```powershell
.\run.bat scan                                  # BTC и ETH на 1hour, 4hour, 1day
.\run.bat --set TAKE_ATR=0 --set TRAIL_ATR=3 scan  # без тейка, с трейлинг-стопом
.\run.bat scan --symbols SOL-USDT,XRP-USDT --timeframes 4hour,1day
```

`--set КЛЮЧ=ЗНАЧЕНИЕ` меняет любой параметр из `.env` на один запуск.
`TAKE_ATR=0` выключает тейк-профит: трендовые стратегии зарабатывают на редких
больших движениях, и фиксированный тейк их обрезает. Скачанная история
кэшируется в `data/` на 12 часов. В `compare` и `scan` аварийная остановка по
просадке выключена, иначе она обрезала бы историю. В `backtest`, `paper` и
`live` она работает.

### Как выбрать стратегию

`compare` печатает таблицу за весь период и за каждую часть истории (по
умолчанию две половины, количество задаётся `--parts`). Подходит стратегия,
у которой одновременно:

- доход положительный **на каждом** отрезке, а не только на всём периоде;
- profit factor (PF) выше ~1.3: при меньшем значении запас над комиссиями слишком мал;
- просадка заметно меньше, чем у «купить+ждать» за тот же отрезок;
- сделок хотя бы 30: на 5 сделках результат — дело случая.

Стратегия, которая выиграла только на одной половине, скорее всего поймала
удачный рынок. Обычно `trend` и `breakout` зарабатывают на трендовом
рынке и теряют в боковике, а у `meanrev` наоборот. Проверьте несколько пар
(`SYMBOL`) и таймфреймов: на 1-минутных свечах комиссии почти всегда съедают
всю прибыль, разумно начинать с `1hour`/`4hour`.

### Несколько пар одновременно

Один процесс торгует одной парой. Для нескольких пар запустите несколько
процессов (в Windows — несколько окон PowerShell):

```powershell
.\run.bat --symbol BTC-USDT paper
.\run.bat --symbol ETH-USDT paper
```

У каждой пары свои файлы состояния и лога: `state_paper_BTC-USDT.json`,
`paper_BTC-USDT.log`. В `paper` у каждого процесса свой виртуальный баланс
`PAPER_BALANCE`. В `live` все процессы берут деньги с одного USDT-счёта и
каждый может занять до `MAX_CAPITAL`, поэтому держите на счёте не больше,
чем `MAX_CAPITAL` × число пар.

### Как читать результат бэктеста

Сравнивайте строку «Доходность бота» со строкой «Купить и держать» и смотрите
на «Макс. просадка». Смысл бота — в меньшей просадке или в заработке на
боковом рынке. Если бот проигрывает простому удержанию и при этом не снижает
просадку, в live его запускать не стоит.

Не подгоняйте параметры под один период: это переобучение. Подберите параметры
на одном отрезке (например, 2023–2024), затем проверьте их без изменений на
другом (2025). Если результат развалился — стратегия не работает.

## Безопасность API-ключа

- Права ключа: только **General** и **Spot Trading**. Права **Withdraw/Transfer
  не включайте никогда**.
- Привяжите ключ к IP-адресу сервера (IP whitelist).
- Лучше создать отдельный саб-аккаунт KuCoin только для бота и положить туда
  ровно ту сумму, которой бот может рисковать.
- `.env` не коммитится (есть в `.gitignore`), а `.htaccess` в этой папке
  не даёт веб-серверу сайта раздавать код и файлы бота.

## Запуск на сервере 24/7

Пример unit-файла systemd, `/etc/systemd/system/kucoin-bot.service`:

```ini
[Unit]
Description=KuCoin bot
After=network-online.target

[Service]
WorkingDirectory=/opt/kucoin-bot
ExecStart=/opt/kucoin-bot/.venv/bin/python main.py paper
Restart=on-failure
RestartSec=30

[Install]
WantedBy=multi-user.target
```

`sudo systemctl enable --now kucoin-bot`, логи: `journalctl -u kucoin-bot -f`
(они также пишутся в `paper_<ПАРА>.log` / `live_<ПАРА>.log`).

## Структура

```
main.py               — CLI: download / backtest / compare / paper / live
bot/kucoin_client.py  — REST-клиент KuCoin (подпись запросов, свечи, ордера)
bot/indicators.py     — EMA, SMA, RSI, ATR, Боллинджер, Дончиан
bot/strategy.py       — стратегии trend / meanrev / breakout, уровни стопа и тейка
bot/risk.py           — размер позиции, дневной лимит, аварийная остановка
bot/brokers.py        — PaperBroker (симуляция) и LiveBroker (реальные ордера)
bot/backtest.py       — бэктест, метрики, сравнение стратегий
bot/runner.py         — торговый цикл одной пары, сохранение состояния
bot/universe.py       — автоматический отбор ликвидных пар со всей биржи
bot/portfolio.py      — режим auto: портфель из нескольких пар, портфельный бэктест
bot/journal.py        — журнал сделок (CSV) и статистика
tests/                — тесты (pytest), работают без сети
```

Тесты: `pip install pytest && python -m pytest -q`.
