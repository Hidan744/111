# Рассылка именных писем

Инструмент для веерной рассылки персонализированных деловых писем (директорам/ген.
директорам) с автосборкой шапки, фирменным бланком, контролем скорости отправки и
отчётностью. Вся инфраструктура рассчитана на размещение на территории РФ: своя БД,
свой сервер, отправка через SMTP-ящик заказчика (без зарубежных ESP).

## Быстрый старт (локально, для разработки)

```bash
cp .env.example .env
# впишите POSTGRES_PASSWORD и CREDENTIALS_ENC_KEY (см. подсказку в .env.example)
docker compose up -d db
npm install
npm run prisma:migrate:dev
npm run dev
# приложение на http://localhost:3000
```

## Развёртывание на сервере в РФ (продакшн)

Приложение — обычный Docker Compose стек (`app` + `db`), не привязанный к конкретному
облаку. Подходит любой VPS/выделенный сервер в России с Docker:

1. Арендовать сервер: Yandex Cloud, VK Cloud, Selectel или Timeweb Cloud — для этой
   нагрузки (десятки писем в день) достаточно 2 vCPU / 4 GB RAM.
2. Установить Docker и Docker Compose на сервер.
3. Склонировать репозиторий, зайти в папку `mailer`.
4. `cp .env.example .env`, заполнить:
   - `POSTGRES_PASSWORD` — сгенерировать сложный пароль;
   - `CREDENTIALS_ENC_KEY` — выполнить `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`, вставить результат;
   - `PUBLIC_BASE_URL` — публичный адрес, по которому сервер будет доступен (нужен для
     ссылок трекинга и отписки в письмах, например `https://mailer.вашкомпания.рф`).
5. `docker compose up -d --build` — поднимет Postgres и приложение, применит миграции.
6. Настроить обратный прокси (nginx/Caddy) с TLS-сертификатом на `PUBLIC_BASE_URL`.
7. Зайти в приложение → **Настройки** → подключить корпоративный почтовый ящик
   (SMTP для отправки, IMAP для чтения ответов).

## Настройка почтового ящика

Приложение не привязано к конкретному провайдеру — в Настройках вводятся любые
SMTP/IMAP реквизиты. Рекомендуются провайдеры с серверами в РФ:

- **Yandex 360 для бизнеса**: `smtp.yandex.ru:465` (SSL), `imap.yandex.ru:993` (SSL).
  Пароль — не от основного аккаунта, а "пароль приложения", создаётся в настройках
  безопасности Яндекс ID.
- **VK WorkMail** — аналогично, реквизиты SMTP/IMAP выдаются в панели администратора домена.

### Чек-лист доставляемости (чтобы письма не улетали в спам)

Настраивается на стороне DNS домена отправителя (у регистратора/хостинга):

- [ ] **SPF**-запись домена включает сервер отправки (провайдер почты обычно даёт
      готовую строку, например `v=spf1 include:_spf.yandex.net ~all` для Yandex 360).
- [ ] **DKIM** включён у почтового провайдера и подтверждён DNS-записью.
- [ ] **DMARC**-запись добавлена (хотя бы `v=DMARC1; p=none; rua=mailto:...`).
- [ ] Новый домен/ящик — прогрет: первые 1-2 недели объём писем наращивается постепенно,
      а не сразу на полную мощность.
- [ ] В каждом письме есть рабочая ссылка отписки (уже реализовано) — снижает жалобы
      "это спам".
- [ ] Список получателей не содержит "мёртвых"/несуществующих адресов (снижает bounce rate).

## Как работает рассылка

1. **Настройки** → добавить почтовый ящик (SMTP/IMAP), фирменный бланк (jpg
   колонтитулы + текст реквизитов), схему нумерации исходящих писем.
2. **Кампании** → новая кампания: тема, текст письма (тело — не меняется в ходе
   рассылки), выбрать ящик/бланк/нумерацию, задать окно отправки и порог ротации текста.
3. Импортировать получателей из Excel (.xlsx) с колонками: Компания, Должность,
   Фамилия И.О., Имя Отчество, Email.
4. Запустить кампанию. Планировщик каждую минуту проверяет рабочее окно (по умолчанию
   9:00–17:00 по Перми, обед 12:00–13:00) и отправляет очередное письмо не чаще, чем
   раз в 5 минут.
5. Каждые 50–100 отправленных писем (настраивается) рассылка автоматически ставится на
   паузу — нужно зайти в кампанию и подтвердить/поправить тему и текст письма, чтобы
   продолжить (так требование ТЗ "менять текст каждые 50-100 писем ради антиспама"
   выполняется осознанно, без автоматической подмены согласованного текста).
6. Открытие писем фиксируется трекинг-пикселем (оценочная метрика — часть почтовых
   клиентов блокирует изображения по умолчанию).
7. Ответы определяются по входящим в IMAP (сопоставление по заголовкам письма).
8. Отчёт по кампании (отправлено/открыто/ответов, по каждому получателю) скачивается
   в Excel кнопкой на странице кампании в любой момент.

## Структура проекта

```
src/
  server/       — Express-приложение и маршруты админки
  scheduler/     — джобы отправки и чтения ответов (node-cron)
  mail/          — рендер письма, отправка через SMTP
  import-export/ — импорт получателей из Excel, экспорт отчёта
  templates/     — EJS-вьюхи админки
  lib/           — БД, шифрование, расчёт рабочего окна, нумерация
prisma/          — схема БД и миграции
```

## Известные ограничения (честно, для заказчика)

- Открываемость писем — оценочная метрика: многие почтовые клиенты по умолчанию не
  подгружают картинки, поэтому реальный % открытий обычно выше, чем показывает отчёт.
- Формат исходящего номера ("0210/186" из ТЗ) реализован как настраиваемый шаблон —
  при внедрении нужно уточнить у заказчика точную схему нумерации (что означает "0210")
  и задать её в Настройках → Нумерация.
- Письмо, не отправленное из-за сбоя (например, недоступен SMTP), помечается статусом
  "ошибка" и остаётся в отчёте — автоматических повторных попыток нет, при необходимости
  добавляется отдельной доработкой.
